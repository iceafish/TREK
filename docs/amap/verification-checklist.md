# 高德接入 · 人工验证清单

> 覆盖 `01`–`05` 五个包的全部人工验证项。自动化测试（约 2.3 万项）已覆盖坐标
> 转换的数值正确性、契约形状与回归回归面；本清单只列**必须由人判断**的部分：
> 视觉位置、交互手感、浏览器面板观察、跨 provider 的一致性。
>
> 逐项标注了来源包。每项包含：操作步骤 → 预期结果 → 对应的功能流程说明。

---

## 0. 环境准备

### 0.1 凭据加载（一次性）

三个键需要在**服务端进程**里可见。两种方式任选：

```bash
# 方式一：让 server 进程读根目录 .env（推荐，和生产一致）
cd server
DOTENV_CONFIG_PATH=../.env node --require tsconfig-paths/register dist/index.js

# 方式二：把 .env 放到 server/ 下（dotenv 默认读 cwd）
```

> ⚠️ 直接 `pnpm run dev` 时 server 的 cwd 是 `server/`，**读不到仓库根的
> `.env`**（dotenv 按 cwd 找）。表现为：地图加载 503 / 设置里无 amap_js_key。

### 0.2 种子数据

- 一个含 **6 个北京地点**（如天安门、故宫、景山、北海、王府井、前门）的行程
  —— 用于渲染器/坐标验证。
- 同一行程加一条**航班预订**（北京 → 上海，含 from/to 端点）—— 用于大圆弧验证。
- 已知坐标对照：天安门 WGS84 = `(39.9087, 116.3912)`；高德底图上正确的落点
  是其 GCJ-02 位置 `(39.9101, 116.3974)`（偏移约 +550 m，肉眼可辨）。

### 0.3 provider 切换

设置 → 地图 → Map Provider 选 **AMap 高德**（或在管理员默认值里设为实例默认）。

## 1. 坐标层地基（01 包）

**功能流程**：数据库/Dexie/REST 一律 WGS84；仅在与高德交互的边界上转换为
GCJ-02。搜索结果、地图标记、路线几何的坐标全部经过同一对正反变换，误差在
往返中抵消。

| # | 操作 | 预期 |
|---|---|---|
| 1.1 | 搜索「天安门」，把结果加进行程 | 返回的 lat/lng 与真实 WGS84 位置一致（可用任意 WGS84 坐标查询工具比对）——**不带** GCJ-02 偏移 |
| 1.2 | 切到 amap 渲染器查看该地点标记 | 标记落在高德底图上天安门的正确位置（GCJ-02 投影），与高德官方 App 对照无肉眼可见偏移 |
| 1.3 | 同一行程切回 mapbox-gl / leaflet | 标记仍在同一真实位置（三套渲染器读同一 WGS84 数据） |
| 1.4 | 天气 / 时区 / Atlas 国界判定（非地图功能） | 与接入前一致 —— 这些消费同一坐标，若坐标层出错会在这里最先显形 |

## 2. 渲染器基础（02a 包）

**功能流程**：`MapViewAuto` 按 `map_provider` 选择渲染器；amap 分支经懒加载
取回 JSAPI（`use()` 挂起 → Suspense 显示 Leaflet 兜底），安全配置只带
`serviceHost`（指向本站 `/_AMapService`），密钥不下发。

| # | 操作 | 预期 |
|---|---|---|
| 2.1 | DevTools Console | 无 `INVALID_USER_KEY` / `USERKEY_PLAT_NOMATCH` 等鉴权报错；底图左下角出现高德审图号 |
| 2.2 | DevTools Console 输入 `window._AMapSecurityConfig` | 只有 `serviceHost`（形如 `https://<本站>/_AMapService`），**没有** `securityJsCode` 字段 |
| 2.3 | 观察首次加载 | JSAPI 加载期间短暂显示 Leaflet 兜底图，随后切换为高德（无白屏、无报错卡片） |
| 2.4 | 悬浮在地点标记上 | 跟随光标的名称/分类/地址卡片出现；移开即消失；拖动地图时卡片立即收起 |
| 2.5 | 缩小地图到多个地点聚合 | 出现深色圆形聚合泡 + 数量；**点击聚合泡**：展开到该簇范围 |
| 2.6 | 双指/触屏长按地图 600ms | 弹出「在此添加地点」表单；随后的抬手**不会**误触发一次地图点击（选中不应被清除） |
| 2.7 | 桌面右键地图 | 同长按，弹出添加表单 |
| 2.8 | 拖动（HTML5 拖拽）一个地点标记到右侧日程 | 该地点被加入对应日期（与 Leaflet/Mapbox 行为一致） |
| 2.9 | DevTools Console 输入 `window.__trek_map instanceof window.AMap.Map` | `true`（调试句柄指向高德实例） |

## 3. 叠加层（02b 包）

**功能流程**：日程路线、预订交通线、POI 探索、插件贡献层全部在服务端完成
GCJ⇄WGS 转换后才绘制；回调（点击坐标、bbox）返回 WGS84。

| # | 操作 | 预期 |
|---|---|---|
| 3.1 | 选择某天（有 ≥2 个已定位地点） | 出现蓝色路线折线（深色描边 + 亮蓝内芯），贴合道路走向；切驾车/步行重算后折线更新 |
| 3.2 | 导入过 GPX 轨迹的地点 | 轨迹按其颜色（手选色/类别色/默认蓝）绘制，手选色的轨迹带白描边 |
| 3.3 | 点击一条轨迹 | 选中对应地点（侧栏定位到它） |
| 3.4 | 插件路线带充电站/服务区（vias） | 站点显示为小圆点，视觉弱于日程站点；点击显示「标签 · 停留时长」 |
| 3.5 | 开启一条**航班**预订的连接线 | 两端机场出现交通图标药丸（含机场代码）；连接线为大圆弧且平滑，无横穿整图的直线跳变 |
| 3.6 | 点击机场药丸 | 打开对应预订（侧栏定位/弹窗） |
| 3.7 | transit 类型预订（有真实路径数据） | 彩色线路带白色描边，步行段为灰色虚线 |
| 3.8 | 开启地图上的 POI 探索 pill，选一个类别 | 出现彩色针脚（颜色与 pill 一致）；悬浮显示名称卡片；点击触发 onPoiClick 行为 |
| 3.9 | 在 amap 与 mapbox-gl 间来回切换 | 上述叠加层（路线/预订/POI）的**位置**一致、**视觉层级**一致（路线在插件层之上、标记在最上） |

## 4. 服务端 provider 与代理（03 包）

**功能流程**：搜索/补全/详情/逆地理/POI 的数据源在服务端切换到高德 Web
Service；坐标在 provider 内部转回 WGS84 后才进控制器。`/_AMapService` 把
JSAPI 的服务调用转发到 restapi.amap.com 并注入 jscode（仅服务端可见）。

| # | 操作 | 预期 |
|---|---|---|
| 4.1 | DevTools Network 面板过滤 `restapi.amap.com` | **没有**浏览器直连高德 REST 的请求（搜索/POI 走 `/api/maps/*` 本站端点） |
| 4.2 | DevTools Network 面板找 `/_AMapService/` 请求 | 存在（JSAPI 服务调用经本站代理）；**响应 URL 与请求参数中均无 `jscode` 明文回显给页面逻辑**，密钥只在服务端拼接 |
| 4.3 | 未登录（无痕窗口）打开一个公开分享页（含地图） | 地图正常渲染 —— 代理对匿名放行（限流内） |
| 4.4 | 高频刷新分享页（>60 次/分钟） | 收到 429 —— 限流生效，代理未变成无限流端口 |
| 4.5 | curl 访问 `/_AMapService/v4/anything` 或用 POST | 404 / 405 —— allow-list 外前缀不可达 |
| 4.6 | 删掉 `.env` 里 `AMAP_WEB_SERVICE_KEY` 后重启再搜索 | 回落到 OSM 数据源（`source: 'openstreetmap'`）—— 未配置即降级，不报错 |

## 5. 路径规划服务端化（04 包）

**功能流程**：`RouteCalculator` 的三个导出（`calculateRoute` /
`calculateRouteWithLegs` / `calculateSegments`）签名不变，内部改调
`POST /api/maps/route`；服务端逐段调高德并解析 polyline，客户端缓存保留为
第一层。

| # | 操作 | 预期 |
|---|---|---|
| 5.1 | 多站点日程，依次切换 驾车 / 步行 / 骑行 | 三种路线都绘制且**贴合道路**；时长为高德的真实估计（步行不再是简单的距离÷5km/h） |
| 5.2 | DevTools Network 面板过滤 `router.project-osrm.org` 和 `routing.openstreetmap.de` | **零请求**（自动化测试已断言，此处为人工复核） |
| 5.3 | Network 面板看 `POST /api/maps/route` | 请求体为 WGS84 途经点 + profile；同一组途经点第二次触发时命中服务端缓存（响应明显更快） |
| 5.4 | 侧栏的每段距离/时长 | 与地图折线逐段对应（一段一个连接器），行程总时长合理 |
| 5.5 | 断网（或停掉外网）后重算路线 | 调用失败回退为直线或维持上一次结果——**不白屏、不崩**（乐观降级路径） |
| 5.6 | 插件 routeProvider 的 `plugin:<id>/<profile>` 切换 | 与底图 provider 无关，照常工作（契约未动） |

## 6. 降级面（05 包）

**功能流程**：高德条款禁止存储其服务数据，因此 amap 模式下离线瓦片预取
硬关闭（入口 + 内部双道守卫 + SyncMeta 清理），设置页与离线页**明示**这一
限制；自定义底图输入隐藏但不删除已存值；Studio 图书在 amap 模式回落到
矢量国界轮廓。

| # | 操作 | 预期 |
|---|---|---|
| 6.1 | amap 模式下打开行程，DevTools → Application → Cache Storage | **没有**任何高德域名的条目；`map-tiles` 等缓存中也没有 amap URL |
| 6.2 | 地图设置页（amap 模式） | 出现「高德底图不支持离线地图下载」提示；**自定义底图模板输入项与其预览不显示** |
| 6.3 | 离线设置页（amap 模式） | 瓦片预取区块出现同样的「不支持离线」提示 |
| 6.4 | 切回 mapbox-gl / leaflet 再看地图设置页 | 自定义底图输入项**恢复**，且之前保存的模板值**原样还在** |
| 6.5 | amap 模式下登录/刷新（触发 tripSync） | SyncMeta 的 tilesBbox 不再被写入/保留为旧值（DevTools 查 IndexedDB → offlineDb → syncMeta） |
| 6.6 | Studio 新建图书，添加地图元素（amap 模式） | 来源只提供「矢量国界轮廓」；元素为矢量轮廓、可正常导出 PDF，印刷放大不糊 |
| 6.7 | （回归）非 amap 模式的 Studio | relief / satellite 选项照常出现 |
| 6.8 | 移动端（≤768px）设置 → 地图 | 与桌面一致：amap 提示 + 模板输入隐藏 |

## 8. 已知存量问题（非本批改动引入，勿误报）

以下现象在**干净的 dev 基线**上同样复现，已在验收时逐项比对：

- 客户端 e2e：`create-trip` / `trip-planner` / `reorder-arrows` 等 app 用例
  45s 超时，截图项目读 `e2e/.tmp/seed.json` 失败（全新环境必然，与
  `seed.setup` 的产物被 gitignore 有关）。
- 服务端测试：`mcp discovery` ×3、`GATE-001/004`、auth 限流（AUTH-004/018/019
  轮流）为时序/环境抖动；`atlas locate` 依赖外网，离线环境 15s 超时。
- 客户端 lint 有 1400 条**既有** warning（0 error）；地图相关新文件在
  theme:lint 的豁免清单内（注入式地图 HTML 无法走外观令牌，既有惯例）。

## 附：一轮完整验证的建议顺序

1. 起 server（含键）+ 起 client → 登录。
2. 按 §2 验证渲染器基础 → §3 叠加层 → §5 路径规划（同一行程连续做完）。
3. 按 §1.1 抽查一个搜索结果坐标 → §1.2–1.3 对照三渲染器。
4. 按 §6 过一遍降级面（设置页 / 离线页 / Cache Storage / Studio）。
5. 按 §7 确认 Atlas 与公交换乘。
6. 按 §4 收尾核对代理与密钥边界。
