# 01 · 坐标层

> 开工前先读 [00-constraints.md](00-constraints.md)。

**前置**：无。**需要凭据**：不需要（纯离线计算）。
**这是所有后续工作的地基，必须先独立合入。**

## 目标

在 `shared/` 中实现 WGS84 ↔ GCJ-02 双向转换，并用 lint 闸门锁住它的使用范围。

本任务**只做转换层本身**，不涉及任何地图渲染器、不涉及服务端 provider。

## 为什么放 `shared/`

服务端和客户端都要用（服务端要把高德返回的 GCJ-02 转回 WGS84 再交给控制器；客户端要在渲染
边界双向转换）。抄两份就违反了 CLAUDE.md 的「单一真值优于手工同步」。它是零依赖纯函数，
正是 `shared/` 该装的东西。

## 创建文件

```
shared/src/geo/gcj02.ts        正反变换 + outOfChina
shared/src/geo/coords.ts       Wgs84LngLat / Gcj02LngLat 品牌类型
shared/src/geo/gcj02.spec.ts   回归基线测试
```

并在 `shared/src/index.ts` 导出。

## 实现要求

1. **正变换 `wgs2gcj`** 使用公开的 GCJ-02 偏移算法，Krasovsky 1940 椭球：
   `a = 6378245.0`，`ee = 0.00669342162296594323`。

2. **逆变换 `gcj2wgs`** 使用不动点迭代，**固定 3 次**：

   ```
   wgs₀ = gcj
   wgs_{n+1} = gcj − (wgs2gcj(wgs_n) − wgs_n)
   ```

   因为偏移函数 δ 的雅可比范数远小于 1，这是压缩映射，收敛由数学保证。实测 3 次已达
   0.03 毫米，第 4 次无收益。**迭代次数不要做成参数** —— 它是经过验证的常量，暴露出去只会
   让调用方乱调。

3. **`outOfChina` 判定**：经度 `73.66–135.05`、纬度 `3.86–53.55` 之外**恒等返回**。
   正反两个方向都必须做这个短路。这是一个粗略包围盒，边界处变换不连续；本轮只做大陆目的地
   所以无影响，但函数从第一天就要在。港澳台落在包围盒内会被变换，与高德实际行为一致。

4. **品牌类型**：`Wgs84LngLat` 与 `Gcj02LngLat` 必须**不可互换** —— 方向写反或重复转换要在
   编译期报错。

   > 本仓库目前**没有**品牌类型的先例。这是刻意引入的新惯例，不要因为「周围代码没有」
   > 而省略。它防的正是这个方案里最难查的一类 bug：坐标系错配不会崩溃，只会让点位悄悄
   > 偏移几百米。

## 测试基线

以下数值来自 2026-09-07 的实测，脚本见 `validate-gcj.mjs`（以高德官方转换接口为基准，
大陆 30 点位）。

**往返闭合** —— 对下列点位断言 `gcj2wgs(wgs2gcj(p))` 与 `p` 的大圆距离 `< 1e-4` 米。
实测最大值约 `2.5e-5` 米，`1e-4` 是留有余量的门槛。

**正变换精确快照** —— 断言 `wgs2gcj` 的**输出坐标**与下表一致（容差 `1e-6` 度）：

| 点位 | 输入 WGS84 (lat, lng) | 期望 GCJ-02 输出 |
|---|---|---|
| 天安门 | 39.9087, 116.3912 | `39.9101013, 116.3974413` |
| 外滩 | 31.2393, 121.4905 | `31.2373137, 121.4949662` |
| 大昭寺 拉萨 | 29.6530, 91.1320 | `29.6502782, 91.1335435` |
| 敦煌莫高窟 | 40.0410, 94.8090 | `40.0416788, 94.8101238` |
| 漠河 | 53.4700, 122.3500 | `53.4720265, 122.3575070` |
| 三亚湾 | 18.2400, 109.5000 | `18.2383350, 109.5041180` |

> **这张表比往返闭合断言更重要，不要省略。** 往返闭合只检验实现的**自洽性** —— 一个符号
> 写反、或经纬度写颠倒的实现，只要正反一致，往返测试照样全绿。只有拿真实期望输出比对才能
> 抓住这类错误。上表的值由已通过官方接口验证的实现生成（该实现与高德官方变换在天安门处
> 相差 0.13 米），因此可当作基准。
>
> 注意几个点位的方向特征，它们是很好的判别器：天安门**纬度增、经度增**；外滩**纬度减、
> 经度增**；三亚湾**纬度减、经度增**；敦煌的位移量特别小（约 128 米，其余多在 400–620 米）。
> 一个把偏移量算反的实现会在第一行就失败。

**境外恒等** —— 东京 `(35.6586, 139.7454)`、巴黎 `(48.8584, 2.2945)` 必须**严格相等**
（不是近似相等）。

**不要写调用高德接口的测试。** CI 无 key、无网络、有配额限制。与高德官方接口的比对是一次性
人工验证，已完成，结论：东部（≥112°E）误差 max 0.63 m，西部 max 6.92 m，均在门槛内。

## lint 闸门

在 client 与 server 的 ESLint 配置中加 `no-restricted-imports`，使 `shared/src/geo/gcj02`
只允许被以下两处导入：

```
client/src/components/Map/engines/amap/**
server/src/nest/maps/providers/amap/**
```

这两个目录本任务不创建，**规则先就位**。

没有这道闸门，GCJ-02 早晚会顺着某个「顺手」的 import 泄进 store 或 repo，然后天气查询和
时区判定开始静默地错 —— 不报错，只是结果不对。

参照物：本仓库已有 `lint:pages`、`check:gl-split`、`validate-route-guards.ts` 这类闸门，
这条完全同构。

## 注释要求

在 `gcj02.ts` 顶部注释中写明：

- 迭代次数为什么固定 3 次（实测数据）
- 西部地区约 7 米的近似误差**是已知且可接受的**，不是 bug
- 为什么禁止用 `AMap.convertFrom`（误差抵消）

否则半年后有人看到「拉萨偏 7 米」会当成缺陷去「修」，而任何修法都会污染非地图消费者。
